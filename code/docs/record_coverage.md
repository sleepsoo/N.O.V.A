# 문진 사실 → S칸 기록 반영률 실측 (2026-10-14, 읽기 전용 분석)

대상 코드: `code_js/agent`. `facts.py`·`subjective.py`·`record.py`·`note2.py`는 code_v5·code_v2c와 바이트 단위로 같다(`code/agent/note2.py`만 다름).
실제 경로(V2=1): `run.py` → `facts.extract` → `note2.write_subjective`(= `write_s_narrative`(LLM) + `render_fixed`(코드)). `subjective.py`의 judge/render_history는 v1 폴백 경로라서 V2에서는 hpi 템플릿 폴백에만 쓰인다.

**중요 전제**: `sim-*` 실행본 6개는 summary.json 기준으로 Doctor 모델과 환자 시뮬레이터가 모두 **로컬 gpt-oss-20b**다. 따라서 사실 추출과 S 서술의 품질은 서버(luna)보다 낮다. 서버 실행본 5개(v2c 2개, v2-final 3개)가 실제 대회 조건이다.

판정 기준: 환자 답 한 줄을 원자 사실로 쪼갠다. 짝 질문에 "둘 다 없어요"라고 답하면 음성 사실 2개로 센다. 같은 내용이 반복되면 1개로 친다. "네, 알겠습니다" 같은 수긍은 사실로 세지 않는다. 시작 정보(턴 0)는 세지 않았다. S의 어느 칸이든 의미가 일치하면 반영으로 본다. 진찰은 EXAM 수락 행이 O칸에 들어갔는지만 봤고, 거절된 진찰은 제외했다.

## 3. 코드 원인 (확인과 추정 구분)

**A. `note2.render_fixed` 누락 점검이 hpi/ice 사실과 pol "?" 사실을 건너뜀 — 확인, 16건 (로컬 15, 서버 1)**
- 위치: `code_js/agent/note2.py` 157–160행.
  ```python
  if f['key'] != 'other' or f['sec'] in ('ice', 'hpi'):
      continue
  if f['pol'] not in '+-' and not (f['sec'] == 'fh' and f.get('detail')):
      continue
  ```
- 사실표(summary.json `findings`)에는 들어 있다. 예: S01-v5 F13·F14 흑변/혈변(-), F15 맹장염 걱정, F18 열 37.0, F19·F20 소변, F21 진통제, F25 이전 진료. S06 F21·F22 우울/수면(-). v2-final C01 F8 "7년 전부터". 이런 사실은 sec가 hpi/ice이거나 pol이 "?"라서 보충 대상에서 빠진다. 그 뒤에는 `write_s_narrative`(EFFORT_S=**low**)가 hpi 서술에 넣어 주기만 기대한다. 서술 LLM이 빠뜨리면 그대로 사라진다.
- 덧붙임(확인): 20b는 음성 증상을 고정 키(ros.Melena 등)가 아닌 `other`로 뽑고, sec도 hpi로 붙이는 경우가 많다. 그래서 ROS 고정 칸(Melena/Hematochezia/Nausea 등)이 정보가 있어도 빈칸으로 남는다(S01-v5).

**B. 설명 단계 환자 발언을 원천 배제 — 확인, 13건 (로컬 7, 서버 6)**
- `facts.qa_rows`(`facts.py` 21행)와 `subjective.SKIP_PHASES`(29행)가 `phase in ('empathy','explain','explain-answer')`를 버린다. `write_s_narrative`의 문답 원문도 `qa_rows`를 쓰므로, 설명 단계 발언은 사실표에도 서술에도 들어가지 않는다.
- 서버 6건은 모두 환자의 마지막 질문·기대("치료하면 좋아질까요", "치료 기간")다. 로컬 7건 중 4건은 새 증상(야간 발한, 오한·37.8도, 빈뇨 10회, 발열-)이었다. 다만 20b 시뮬레이터가 설명 턴에 증상을 흘리는 버릇일 가능성이 있다(추정).

**C. 사실 추출(facts.extract) 단계 누락·오기록 — 확인(사실표에 없음), 11건, 전부 로컬 20b**
- 이런 경우가 있었다: 짝 질문이나 부분 부정을 하나로 합침("검거나 피" → 변혈없음 하나, "설사까지는 아니지만" → 누락). 한 턴의 두 번째 사실 누락(눈 뻑뻑, 스트레스 없음, 부친 투석 사망). detail 누락(2개월). 턴 정렬 오류(C10-v5 F23: 턴 21이 "치료계획"으로 붙음). 오분류(인후통(-) → 발열(-), 더부룩 → 복부부기 +).
- 서버(luna, effort medium)에서는 이 유형이 0건이다. 모델 성능 문제일 가능성이 크다(추정). 프롬프트 규칙은 이미 있지만("한 턴에 여러 사실이면 여러 개", "묽은 변≠설사") 20b가 지키지 못한다.
- 글자 수 제한(label 16자, detail 30자 절단)이 원인인 누락은 관찰되지 않았다(확인).

참고(커버리지 계산과 무관한 품질 문제, 로컬만 해당): S에 근거 없는 서술이 들어가 있다. C10-v5 hpi "고조혈반을 통한 혈압·혈당 측정", S03 "NRS 5점", S01-js "발열 -". 채점에서 감점 위험이 있다.

## 4. 결론

- **전체 반영률은 87.1%(271/311)다. 실제 대회 조건인 서버는 95.1%(137/144), 로컬 20b는 80.2%(134/167)다.** O칸 반영률은 100%다.
- **턴을 쓰지 않고 정보수집을 올릴 수 있는 기대 폭**(누락 ÷ 전체 문진 사실)
  - 서버 기준 약 **+4.9%p**(7/144). 6건은 설명 단계 질문·기대(B), 1건은 pol "?" 탈락(A)이다.
  - 로컬 기준 약 +19.8%p(33/167). A로 9.0%p(15건), B로 4.2%p(7건), C로 6.6%p(11건)다.
  - 전체 11개 기준 12.9%p(40/311)다.

### 최소 변경 제안 (턴 예산·문진·진찰 흐름은 건드리지 않음)

1. **`code_js/agent/note2.py` `render_fixed` 누락 점검 완화** (A를 막음. 로컬 15건, 서버 1건)
   - `sec in ('ice','hpi')` 건너뛰기를 없앤다. hpi의 음성·증상 사실은 `ros` Others에, ice 사실은 hpi 끝에 "걱정·기대 : …" 한 줄로 붙인다.
   - pol "?"도 detail이 있으면 `라벨 : detail` 형식으로 받는다.
   - 기존 라벨·detail 중복 검사(`lab in sec_text`)는 그대로 두어 중복을 막는다.
2. **`code_js/agent/facts.py` `qa_rows`에서 설명 단계 환자 답 포함** (B를 막음. 로컬 7건, 서버 6건)
   - `explain`/`explain-answer` 행을 버리지 않는다. 대신 답이 단순 수긍(`^네[, ]*(알겠|검사받|조심|그럴|바로 올)` 등)이면 빼고, 나머지는 사실 추출 대상에 넣는다.
   - `write_s_narrative`도 `qa_rows`를 쓰므로 hpi의 걱정·기대에 함께 반영된다.
   - 환자 질문은 ice(기대) 사실이 되고, 1번 수정으로 hpi에 남는다.
3. **`code_js/agent/facts.py` `extract` 후처리: 음성 증상을 ROS 고정 키로 매핑하고 sec를 ros로 강제** (A·C 일부. 로컬 위주, 효과는 추정)
   - `validate`에서 key=other이고 pol="-"인 사실의 라벨이 ROS_FIXED 한글명(흑변→Melena, 혈변→Hematochezia, 설사→Diarrhea, 발열→Fever, 오한→Chill 등)과 일치하면 고정 키로 승격하고, 나머지 음성 증상은 sec="ros"로 둔다.
   - 그러면 고정 칸 (+/-)이 채워지고, 1번의 보충 대상에도 확실히 들어간다.
   - 단, 오분류(인후통 → 발열)는 막지 못한다. 서버 luna에서는 해당 건이 없었다.
