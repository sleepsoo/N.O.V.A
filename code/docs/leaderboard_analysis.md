## 0. 결론 요약

1. **리더보드 sol과 샘플 luna는 같은 코드에서도 효율이 8점 차이 난다.** v2c는 리더보드 효율 11.29였고, 같은 계열 v2는 샘플 검증에서 19.42였다 [실측]. 정보수집(−2.8), 검사·추적(−1.5), 진단추론(−1.7)도 sol이 더 낮다. 의사소통은 비슷하다(8.3 대 8.9).
2. **효율 11.3의 직접 원인은 리더보드에서 볼 수 없다.** 대리 지표로 로컬 공식형 sol 채점 31건을 썼다. 이 채점에서 효율은 버전과 턴 수(39~50)에 관계없이 10~14에 모인다(평균 12.0). 턴 수와의 상관 −0.19, 출력 토큰과의 상관 −0.21로 약하다 [실측].
   - 감점 사유 빈도: 사용량 지적 31/31, 설명 분절·반복 20/31, 중복 질문 18/31, 저수익 진찰 16/31, 시작 정보 재질문 10/31, 기록 중복 4/31 [실측].
3. **토큰이 효율을 좌우한다는 가설에는 반증이 있다.** 대회 PDF의 기본 에이전트(C01)는 sol 공식 채점에서 효율 20.000(3회 평균)을 받았다 [실측]. 그 진료는 30턴, Doctor 37회, 출력 18.2k 토큰(입력은 비용 역산으로 약 32.6k), 진찰 거절 6회였다. 우리(출력 8.8k, 거절 0)보다 토큰을 두 배 썼는데 만점이었다. 따라서 토큰 절감은 위생 조치로만 하고 큰 효과는 기대하지 않는다 [추론].
4. **턴을 유지하는 변경만으로 효율 15+를 얻는다는 근거는 없다.** 현실적 기대는 낭비 행동 제거, 토큰 −15~20%, 기록 중복 제거를 합쳐 **+0.5~2.0(→ 약 12~13.5)** 이다 [추측].
   - 15+ 가능성은 턴·구조를 바꾸는 실험(§7.2)으로만 확인할 수 있다.
   - 다만 로컬 sol은 턴을 늘려 커버리지를 올린 쪽을 더 좋게 봤다. 50턴 probe50이 44턴보다 +2.7이었다 [실측, 3증례 1회].
5. **턴 소모 없이 확실히 올릴 수 있는 것은 A/P 서술과 기록 정합이다.**
   - 검사·추적: 감별진단-검사 연결, 조건부 검사의 시행 조건, 의뢰 기준, 추적 항목 → +0.5~1.2 [추측]
   - 진단추론: 근거 있는 감별 4~5개와 환자 걱정 질환 → +0.2~0.7 [추측]
   - 정보수집: 활력징후 직접 측정, 표 밖 진찰 제거, 설명 중 환자 질문 기록 → +0.3~0.9 [추측]
6. **최종 평가는 sol·Claude·Gemini 평균이고 luna는 들어가지 않는다.** luna 샘플 검증은 폭락 감시용 대리 지표로만 쓴다. 채점기에 관계없이 인정될 요소를 우선한다.
   - 거절 0, 중복 0
   - 표 행 적중
   - 물은 범위 그대로 기록
   - 근거 인용
   - 감별-검사 연결
   - 질문에 실제로 답함

### 4.4 반증: PDF 기본 에이전트(sol 공식, 10-11) [실측]

- 가능한 설명 [추측]

  - H5: 설명 턴(우리 9~11 vs 기본 2)을 "분절"로 본다.
- **어느 가설이든 "출력 토큰을 줄이면 효율이 크게 오른다"는 지지하지 않는다.** H1·H5는 턴·설명 구조, H2는 원화 비용이다. 이것들은 v7 기본안(턴 유지)으로는 시험되지 않고 별도 실험(§7.2)이 필요하다.

### 7.2 1일 1회 리더보드 운영안

- 리더보드는 최종 순위가 아니고 최종 평가는 선택한 제출 하나를 다시 채점한다. **리더보드 날짜는 학습용 실험 슬롯으로 쓴다** [추론].
- 하루에 한 요인만 바꾸고 영역별 점수로 읽는다.
- v7은 코드 수정 없이 프리셋 파일(`preset.json`)로 변형을 만들 수 있게 한다(v7_spec C7).

### 7.3 최종 제출 선택 규칙 [추론]

- 리더보드 단일 결과보다 영역별로 일관되게 좋은 쪽을 고른다(3점 미만 차이는 동률로 본다).
