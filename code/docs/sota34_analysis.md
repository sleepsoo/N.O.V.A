### 0.1 핵심 문제 5개

1. **문진 턴당 사실 수가 낮다(1.35~1.44개).** 34턴의 문진 16턴이 거의 전부 단일 항목 닫힌 질문이다. 묶음(짝) 질문을 프롬프트로 금지한 근거(프로브 n=6~7)가 틀렸다. 우리 서버 로그 169건과 팀원 224건 모두 **같은 계통 2항목 짝은 대부분 두 항목 모두 답을 받는다**(우리 로그 83%) [실측]. 44→34턴 절단으로 땀·눈·목·근력·생리·흉통/숨참 문항이 통째로 빠졌다 [실측].
2. **마지막 환자 질문이 구조적으로 답을 못 받는다.** `TURN_CAP 35` 설계인데 `explain_loop`의 남은 턴 조건(`turns_remaining <= len(rest)+1`)이 마지막 답을 막아 34턴에서 끝난다. 그래서 "더 궁금하신 점 있으세요?" 뒤 환자 질문(치료 기간)이 항상 미응답이다. 팀원 34턴 채점 2/2가 이 점을 감점했다 [실측].
3. **설명 내용이 채점 항목을 못 채운다.** 걱정(암)에 근거 없는 답, 기전과 증상 연결 약함, 치료 선택지·기간·부작용 대처 없음("부작용도 안내해요"로 미룸), 검사 문장 2개 중복, 공감은 첫 질문 앞 접두뿐이다. 이 접두는 서버가 잘라낸다 [실측].
4. **사실 장부(drill)가 필수 문항을 밀어낸다.** 장부 후속 질문이 문진 자리를 먼저 써서 우선순위 1 문항(임신 가능성·기타 지병)이 빠졌다. 팀원 C10 2회차에서 임신 미확인으로 안전 감점이 나왔다. "누가 몇 살쯤"(가족 발병 나이) 같은 저수익 질문은 '불필요'로 지적됐다 [실측].
5. **진찰 8회 중 심음·폐 청진이 빠진다.** 범주 하한 6 + 외관 1 + LLM 1이라 폐 청진이 들어갈 자리가 없다. 활력징후는 시작 정보에 값이 있으면 측정하지 않아 표의 '활력징후 측정' 행도 잃는다. 팀원 채점 2/2가 "심폐 청진 생략"을 지적했다 [실측].

## 2. A. 34턴 SOTA 해부

### 2.1 무엇이 34턴을 만들었나 [실측: `diff -r code_ref/jongseung_v2_fixed code_js7`]

| 변경 | 내용 |
|---|---|
| `run.py` | `TURN_PRESET 't35'` = 문진 16 + 진찰 8 + 설명 9(마지막 '더 궁금하신 점' 포함) + 답 상한 2. `TURN_CAP 35`, `ANSWER_RESERVE 1`, `BATCH_N 7→5`, `PLAN_Q_CALLS 2→3`, `FOLLOW_MAX 4` |
| `encounter.py` | `_cap_turns()`: 남은 턴 = min(서버 잔여, 35 − 현재 턴). `can_act()`에 `turn < TURN_CAP` 안전선 |
| `interview.py` | `left()`가 진찰·설명·답 예약을 먼저 뺀다(35 − (8+9+1+1) = 16). 사실 장부 `drill()` 추가(양성 답 뒤 후속 질문). `plan_q` 프롬프트에 장부 요약 |
| `store.py`(신규) | 답 극성 판정 + `FOLLOWUP` 후속 질문표 + LLM용 요약 |

**설계는 35턴인데 실제로는 34턴에서 끝난다.** `explain.explain_loop`가 답을 하려면 `turns_remaining > len(rest)+1`이어야 한다. 마지막 질문 줄(턴 34)에서는 rest=0, 남은 턴 1이라 1 ≤ 1이 되어 답을 건너뛴다 [실측: 코드 + 두 34턴 대본].
- 결과적으로 효율은 34턴 이득을 봤다.
- 대신 소통은 마지막 질문 미응답 감점을 고정으로 안는다.

### 6.3 I2 — 항목별 응답 판정과 안전 재질문

판정 함수 (`bank2.pair_answered(kw_a, kw_b, reply)`, 우리 169건으로 검증한 규칙):
```python
GENERIC_BOTH = re.compile(r'(둘\s*다|모두|다\s*없|아무것도|그런\s*(증상|병|질환|적|건|것|변화|문제|분|얘기|말))')
def pair_answered(kw_a, kw_b, reply):
    if GENERIC_BOTH.search(reply):
        return True, True
    a, b = bool(re.search(kw_a, reply)), bool(re.search(kw_b, reply))
    if a or b:
        return a, b
    if re.match(r'\s*(아니(요|오)?|아뇨|없|전혀)', reply):   # 맨 부정 = 둘 다 음성
        return True, True
    return True, False                                     # 모호: 첫 항목만 인정(부분 응답 27/29가 첫 항목)
```
- `interview.ask(slot='a+b')`
  - `cl.asked |= {a, b}`로 두 항목을 표시한다.
  - 판정에서 미응답인 항목은 `cl.asked`에서 되돌린다(나중 자리가 나면 단독으로 물을 수 있음).
  - ledger entry에 `pair_items=[(a, label_a, ok_a), (b, label_b, ok_b)]`를 기록한다(기록 단계에서 사용).
- 안전 항목(`SAFETY_REASK = {pmh_allergy, pmh_asthma, ros_cp, ros_dysp, pmh_meds, sb_seizure, sb_last, ps_si}`)이 미응답이고 `REASK_MAX`(1)가 남았으면 다음 턴에 단독으로 다시 묻는다. 예: "약 알레르기는 없으세요?". 이 질문도 문진 15턴 안에 든다.
- `store.FactStore.record`: 짝이면 항목별 극성을 기록한다. 예: "가슴통증 없고 계단 오르면 숨차요" → 흉통 −, 숨참 + → 숨참 후속 후보.

### 6.11 위험 정리 (I·C 공통)

1. **교차 계통 짝** → 첫 항목만 답함(교차 계통·다른 술어 9건 중 두 항목 응답 1건). 계통 사전 검사기로 막고, 은행 짝만 화이트리스트로 둔다.
2. **양성 우세**: 한 항목이 양성이면 그것만 말함. 예: 약 나열 후 영양제 미응답 10건, "고혈압이 있어요"만 답함. 중요 항목을 앞에 두고, 미응답은 기록하지 않으며, 안전 항목만 1회 재질문한다.
3. **사실 추출이 두 항목을 하나로 합침**: 양성은 "눈 돌출·건조(+)"처럼 합쳐도 두 항목명이 남아 대체로 무해하다. **음성 일반화가 위험**하다. 예: "가슴 통증은 없어요" → "흉통·숨참(-)" 기록 → 기록 오류 감점. 코드 판정(I2)과 기록 필터(I3)로 막는다.

### 9.7 진단추론: MAI-DxO 반영 A칸

[외부] Nori et al. 2025(SDBench / MAI-DxO) 요지는 다음과 같다.
- 판정자는 진단을 5점 척도로 매긴다. 5 = 임상적으로 같음, 4 = 사소한 불완전, 3 = 같은 범주이나 주요 오류, ≤2 = 오답.
- 오케스트레이터는 가상 의사 패널을 쓴다.
  - Dr. Hypothesis: 확률 순 감별 갱신
  - Dr. Test-Chooser: 감별을 가르는 검사 선택
  - Dr. Challenger: 고착·반대 증거 점검
  - Dr. Stewardship: 비용 절제
  - Dr. Checklist: 일관성 점검

A칸 설계 [B/C]:
1. **주진단은 병인·형태까지** 쓴다(5점용). 예: "그레이브스병에 의한 갑상샘항진증", "수면제(졸피뎀) 사용장애", "체질성 성장지연". "갑상샘항진증", "불면증", "저신장"처럼 증상·범주 수준이면 4점 이하 위험.
2. 근거는 "사실(턴) → 해석" 4~5줄로 쓰고 양성·음성·진찰을 섞는다.
3. 감별은 가능성 순 4~5개로 하고, 각 줄 = 지지 / 반대 / 판단 / **감별 검사(예상 결과)** 형식이다. 반드시 넣을 것:
   - (a) 놓치면 안 될 질환(Challenger)
   - (b) 환자가 걱정한 질환(C10 암)
4. 감별 검사가 P.tests에 시행 조건과 함께 있게 한다(Test-Chooser). 침습·저수익 검사는 뺀다(Stewardship).

현재 `assess.dx_and_assess`는 1~3을 부분적으로 한다. 4는 v7 C4에서 설계·구현됐으나 미제출이다.

### 9.9 격차 원인 재정렬 (71.6 → 90, 약 18점)

1. **정보 −9~10**: 질문 선택이 주호소 체크리스트에서 나오지 않는다.
   - 범주 은행 6개 + 공통 필수 + ICE 3턴이 고정이라, 감별에 필요한 관련 음성 영역이 통째로 빠진다(소화기 경고, 체질 증상, 기분, 심폐 합병증, 눈·목, 월경).
   - 턴당 핵심 항목이 ~0.8~1.0이다(묶음이면 ~1.3~1.9).
2. **소통 −3~4**
   - PPI(친절도) 행동이 거의 없다. 공감은 잘리는 접두뿐이고 인사·개방형·마무리가 없다.
   - 설명 내용이 얕다.
   - 마지막 질문이 미응답이다.
3. **검사 −2**: P가 effort low로 SAY와 같이 생성된다. 숨은(KB 밖) 증례에서 검사·추적이 포괄적이다.
4. **안전 −2**: 안전 확인 문항이 체크리스트 필수가 아니다. drill이 밀어낸다.
5. **진단 −1**: 감별 구조와 주진단 구체성이 부족하다.

(이전 핵심 문제 1~5는 원인 1·2·4의 하위 증상이다. 문제 5 "심폐 청진 보장"은 §9.1대로 수정한다.)

### 9.12 검증 계획 (개발 키 0)

1. **체크리스트 대리 평가기**(신규, 로컬)
   - C01·C03·C10의 가설 체크리스트(§9.4·§9.5, C03은 모범 기록 S·O에서 같은 방식)를 만든다.
   - transcript의 질문·답과 기록에서 항목 덮임을 판정한다(키워드 + 항목별 판정).
   - 목표: 문진 ≥80%, 진찰 핵심 ≥75%, 설명 슬롯 7/7, 안전 항목 100%.
   - 점수 예측이 아니라 **설계 준수** 지표로만 쓴다.
2. **로컬 시뮬**(`code/tools/local_sim.py`, :8010 gpt-oss-20b)
   - 56행 환자 규칙을 서버 실측에 맞춘다. 같은 계통 짝·병력 나열은 함께 답하고, 음성 3개 묶음은 포괄 음성, 양성이 섞이면 양성 1개.
   - 합성 증례 S01~S06(충수염·편두통·중이염·COPD·추간판·당뇨)로 일반화를 본다.
   - 지표: 턴 34, 문진 항목/턴, 커버리지, 거절 0, 중복 0.
3. **단위 테스트**
   - 묶음 문구 ≤30자, 3항목 이상은 화이트리스트 묶음만 허용
   - `pair_answered` 3항목 확장: 서버 실측 196행 라벨로 '거짓 둘 다' 0건
   - 턴 정산과 마지막 답
   - 안전 항목 필수 보장
4. **luna 샘플 검증**: 실행·폭락 감시용. luna 정보 점수는 문진 수에 민감했으므로(v4 8.7), 정보가 크게 떨어지면 묶음 판정 오류부터 의심한다.

   - D2: 38~40턴(효율 가설 판정).
   - 이후 영역별 보강.
