### 0.1 결론
1. 모체는 `code/`(v3). `code_js`의 지침 레버는 `agent/guidelines.py` 1개 파일 + 주입 9줄이라 이식 비용이 작고, `code/`는 `code_v2c`의 상위 집합이라 같은 코드베이스 안에서 **code_js 재현 대조군**(V3=0·bal44·GUIDE=1)을 그대로 돌릴 수 있다(§2).
2. 정보수집은 40턴에서 **진찰 쪽으로 턴을 옮기는 것**이 유일하게 큰 레버다. 공개 3증례 진찰표의 50~60%가 같은 이름의 범용 12행이다 [실측]. 핵심 8행은 항상 하고, 증례 특이 진찰은 luna 상위 5개까지, 남는 자리는 범용 보조 4행으로 채운다(“core 8 + 특이 ≤5 + flex”). 이렇게 하면 진찰 커버리지가 48%에서 약 63%로 오른다 [추론].
3. 의사소통은 턴 수보다 **배치**가 문제였다. v3 GEN C10 발화에는 기전·걱정 답·재진·생활 문장이 없다 [실측]. 원인은 `v3.explain`의 우선순위 트림(EXPLAIN_N=8)으로 본다 [추론]. 설명 11턴 안에 환자 질문 슬롯 2개(첫 설명 뒤 87%, 마지막 초대 뒤 90%가 질문 [실측])와 꼬리 3턴(재진·경고·되말하기)을 고정한다. 서술문은 서버가 자르지 않으므로 한 문장에 두 항목을 묶는다(서술 915건 중 절단 0 [실측]).
4. 안전 15는 v3 안전 스택(v2c 템플릿 + `say.safety_problem`)을 쓰고, 지침 발췌(hint_plan)에서 치료 섹션과 용량 문장을 빼서 막는다(§6).
5. 기대치(luna 샘플 검증) 중앙값은 **약 85.7점**(범위 82~89)이다. 40턴 하드캡에서 90점이 나올 확률은 10% 미만으로 본다 [추론, §7]. 걸림돌은 정보수집이다. 문진 22문항 + 진찰 16을 다 하려면 약 50턴이 필요하다.

### 0.3 핵심 변경 5가지
1. **진찰 = 핵심 8 + 특이 ≤5 + flex.** 서버 매칭이 확인된 문구를 쓰고, 간·비장 촉진은 복부 촉진보다 먼저 한다. 진찰 커버리지 48%→63% [추론].
2. **턴 하드캡 40과 강제 마무리.** `Encounter`가 `min(서버 잔여, 40−turn)`만 쓰게 한다. 마지막 3턴은 재진·경고·되말하기로 고정하고, 그 앞 2턴은 마지막 질문과 답으로 예약한다.
3. **설명 11턴 재설계.** 질문 슬롯 2개는 대부분 대기 문장을 앞당겨 추가 턴 없이 처리한다. 서술문은 두 항목까지 묶고, luna가 키마다 후보 2개를 내게 한다. 검증기를 통과하지 못하면 템플릿으로 바꾼다.
4. **문진 14.** 공감 턴으로 걱정을 얻고, sweep 직후 새 증상을 주제 개방형으로 묻는다. 짝 질문은 금지(사용자 지시, 음성 선별 예외는 결정 사항 §4.2.2). 배경(과거력·약·가족력·사회력)은 규칙으로 보장하고 지침 발췌는 luna 계획 1회에 넣는다.
5. **안전·기록 정비.** 치료 섹션을 뺀 지침 발췌와 용량 문장 삭제, 수행하지 않은 소견의 음성 단정 제거, ROS·현병력 정합, "다음 방문 시 교육 예정" 삭제, 설명 중 환자 질문(기대)을 S칸에 기록.

## 1. 근거와 새로 확인한 사실

**F1. 진찰표 = 공통 행 라이브러리 + 증례 특이 행 [실측]**
`code/runs/*/session.json`의 `effective_content`(서버 행 코드)를 모두 모았다. 코드는 두 종류다.
- 공통 접두 `gen_`·`hn_`·`ch_`·`abd_`·`bex_`: 예) `gen_vital_signs`, `hn_thyroid_palpation`, `ch_heart_auscultation`, `abd_liver_spleen_palpation`, `bex_leg_pulse_edema`.
- 증례 번호 접두 `c00_`(C01)·`c02_`(C03)·`c09_`(C10): 예) `c00_sedation_anxiety`, `c02_anthropometry`, `c09_pretibial_myxedema`.

여기서 진찰표가 공통 행 라이브러리와 증례 특이 행으로 조립된다고 본다 [추론]. 비공개 증례도 같은 라이브러리를 쓸 가능성이 높다 [추측].

**F2. 세 증례 모두에 있는 범용 12행 [실측]**
전반적 외관 시진, 의식·지남력 평가, 활력징후 측정, 결막·공막 시진, 갑상선 촉진, 흉곽 시진, 폐 청진, 심음 청진, 복부 시진, 복부 촉진, 간·비장 촉진, 하지 말초 진찰.
- 표 크기 대비 비율: C01 12/24, C03 12/20, C10 12/23.
- 두 증례에만 있는 행: 피부 온도·발한(C01·C10), 자세성 떨림(C01·C10), 보행 관찰(C01·C03).
- C01 모범기록 O칸에는 흉곽·복부 시진이 없는데 표에는 있다. 그래서 템플릿 행으로 본다 [추론].
- 갑상선 촉진은 세 증례 모범기록 감별에 모두 갑상선 질환이 있어서, 템플릿 행인지 증례 때문에 들어간 행인지 구분할 수 없다 [추론]. 그래서 v4에서는 조건부로 둔다.
- 우리가 만든 합성 증례 S01~S06에는 이 12행 중 5~11행만 있다(S02·S05는 5행) [실측]. 비관적 OOD 대리 표본으로 쓸 수 있다.

**F3. 서버는 질문만 자르고 서술문은 자르지 않는다 [실측]**
- 전체 SAY 2,458건 중 절단은 36건이고 모두 질문이다(공감 접두 + 질문, 쉼표로 이은 두 질문, "지병이나 수술받은 적" 같은 짝 절).
- 물음표 없는 서술 915건(‘-고’ 연결 156건, ‘;’ 2건, 두 문장 1건 포함)은 절단 0건이다.
- 설명 문장에는 두 항목을 묶어도 된다(예: v2 "1~2주 뒤 재진해요; 낮잠·늦은 카페인 피하세요." 그대로 전달).

**F4. 설명 단계에서 환자가 질문하는 위치 [실측: ledger 63건]**

### 3.2 하드캡 구현 (`agent/encounter.py`)

```python
# __init__
self.turn_cap = int(cfg.get('TURN_CAP', 50))            # v4 프리셋은 40
self.server_remaining = int(session.get('turns_remaining') or 50)
self.turn = max(0, 50 - self.server_remaining)
self.turns_remaining = max(0, min(self.server_remaining, self.turn_cap - self.turn))
# act() 성공 시 (turn 갱신 뒤)
self.server_remaining = int(tr) if isinstance(tr, int) else self.server_remaining - 1
self.turns_remaining = max(0, min(self.server_remaining, self.turn_cap - self.turn))
# act() TURN_USING 거절 시
self.turn += 1; self.server_remaining -= 1
self.turns_remaining = max(0, min(self.server_remaining, self.turn_cap - self.turn))
```

- `can_act()`는 그대로 둔다(`turns_remaining > 0`). 이것만으로 41번째 행동이 나가지 않는다.
- 기존 예산 코드(v3 `_left`, 진찰·설명 루프)는 모두 `turns_remaining`을 보므로 자동으로 상한을 따른다.
- `DIAGNOSE`는 턴을 쓰지 않는다(공지).

### 3.3 예비턴 소모 규칙 (어떤 거절이 나와도 40을 넘지 않음)
1. **단계 경계.**
   - 문진은 `turns_remaining > X + E`(=25)일 때만 진행한다.
   - 진찰 예산은 `min(X_MAX=16, turns_remaining − E)`이다.
   - 설명은 남은 턴을 모두 쓴다.
   - 그래서 문진이 일찍 끝나면 남는 턴은 진찰(flex·특이 추가)로 가고, 설명 11턴은 지켜진다.
2. **문진 거절**("하나씩", 길이). 1턴이 사라지고 재시도하지 않는다. 문진 문항 수만 줄어든다.
3. **진찰 거절**(NOT_SPECIFIC·NOT_RECOGNIZED). 블랙리스트에 넣고 다음 후보로 간다. 진찰 단계는 `turns_remaining == E`에서 멈추므로 설명 턴은 줄지 않는다.
4. **설명 초과**(추가 질문 답). 우선순위가 낮은 항목부터 버린다(§5.3).
5. **시간.** v3의 `QUICK_EXPLAIN_SECONDS`·`RECORD_MIN_SECONDS` 가드를 유지한다. 설명 시작 시 `turns_remaining < 6`이면 빠른 경로(진단 → 재진 → 경고 → 되말하기)로 간다.

### 3.4 38턴 강제 마무리 시퀀스
- `TAIL` = 아직 말하지 않은 [`followup`, (안전 must 중 미발화분), `warning`, `teach`].
- 매 설명 턴 전에 다음을 확인한다.
  1. `turns_remaining ≤ len(TAIL)`이면 `TAIL[0]`을 말하고, 다른 항목과 질문 답은 건너뛴다.
  2. 위가 아니고 `final`이 미발화이며 `turns_remaining ≤ len(TAIL) + 2`이면 `final`을 말한다. 다음 1턴은 답 전용으로 예약한다.
- 기본 시나리오(거절 0): 36턴 마지막 질문, 37턴 답, 38턴 재진, 39턴 경고, 40턴 되말하기. 마지막 3턴은 서술·서술·단일 질문이라 환자가 다시 묻는 일이 거의 없다(F4: 1.3%).

#### 4.1.2 특이 진찰 선택 (luna, plan 호출 안에서)
- **입력**: 주호소, 지금까지 문답(양성·음성), 감별(한·영), hint_interview 발췌(병력·진찰·감별 섹션), 진찰 메뉴(`banks.EXAM_BANK`에서 core·flex·vitals 제외, `id | 문구 | 계통`).

- **코드 규칙**
  1. 버리는 경우: why가 일반론(v3 정규식 `기본|전신|일반|확인|감별|상태|평가|선별`)이거나 4자 미만, 메뉴 밖 id.

     - `spo2`: 호흡곤란·흉통·심부전 맥락만. 활력징후와 같은 행으로 오매칭되고 기록 오류가 난다 [실측 C01].

     - `eye_signs`: 감별에 갑상선이 있을 때만. 표에 없으면 NOT_SPECIFIC [실측 C01].
     - `RISKY_EXAMS`: 카테고리 일치 시만(기존 규칙).
  3. 특이 수 `S` = high 상위 ≤5개. high가 2개 미만이면 mid로 2개까지 채운다.

  - 비공개 표에 템플릿이 없을 때 손실이 작다.
- u12(범용 12 + 특이 상위 2)는 A/B 대안 팔이다(§8.3).

### 4.2 문진 (14문항 + 공감 1)

#### 4.2.1 구조
- **머리(규칙, LLM 없음)**
  - T1 공감(서술): `profile.empathy`.
  - T2 주호소 주제 개방: `topic_q(cc)`. 시작 정보에 있던 사실도 질문으로 확인돼야 인정된다(C03 채점 "시작 정보만 옮긴 병력은 인정하지 않음" [실측]). 효율 판정의 "초기 정보 재질문" 감점보다 이득이 크다고 본다 [추론].
  - [조건] 공감 답의 걱정이 막연하면("큰 병") 다음 턴에 `특히 걱정되는 병이 있으세요?`를 묻는다(v3 `ask_concern` 재사용).
  - sweep1 → 새 증상이 나오면 바로 주제 후속(§4.2.3) → sweep2 → 주제 후속. 음성 답이나 이전과 비슷한 답이면 sweep을 중단한다.
- **plan 호출 1회**(머리 직후, §부록 D1): luna 질문 후보(최대 남은 자리 + 3)와 특이 진찰을 한 번에 받는다.
- **본문(우선순위 큐)**: ① 안전 slot(§4.2.5, 미확인분) → ② luna 상위 2 → ③ 과거력 → ④ 복용약 → ⑤ 가족력 → ⑥ luna 나머지 → ⑦ 사회력 1(하루 일과 또는 음주·흡연) → ⑧ 기분(정신·수면·체중·두근거림 범주일 때). 이미 덮인 항목(`bank2.cover_hits`)은 건너뛴다.
- **꼬리**: `오늘 특히 궁금하신 게 있으세요?`(고정, 마지막 문진).

#### 4.2.2 질문 규칙 (검증기)
1. 기존 v3 `say.question_problem`을 통과해야 한다: 30자, 물음표 ≤1, '-고' 연결 금지, 공감 접두 금지, "다/전부" 금지, 종결형.
2. **신규 `say.pair_problem(q)`**: 단일 항목 강제.
   - 토큰 끝이 `이나|나|와|과|랑|하고`이고 다음 토큰이 있으면 짝으로 본다. 예외 어휘: 얼마나·언제나·누구나·아무나·하나·결과·효과.
   - `~거나` 토큰, 단어 사이 `·`나 `,`도 짝이다.
   - `FINAL_Q`·`TEACH_BACK`은 면제(실측으로 검증된 문구).
3. 중복 차단: `is_similar ≥ 0.75`, v3의 핵심어 부분집합·주제 중복 검사를 그대로 쓴다.
4. 유형
   - 양성이 예상되는 주제(이미 나온 증상의 시점·빈도·양상·악화 요인)는 주제 개방형(답당 2.0사실 [실측 probe]).
   - 감별용 핵심 음성·안전은 단일 닫힌 질문.
   - 음성 소견도 대본 사실로 인정된다(체크리스트 범주 "음성 소견").
5. **`PAIR_POLICY` — 결정 필요**
   - 기본 `strict`: 사용자 지시대로 짝 금지.
   - 대안 `negscreen`: 음성이 예상되는 선별 짝 화이트리스트만 허용. 예) `고혈압이나 당뇨 있으세요?`, `결핵이나 간염 앓은 적 있으세요?`, `수술이나 입원한 적 있으세요?`, `가슴 통증이나 숨참은 없으세요?`
   - F11 실측: 음성 답의 절반 이상이 두 항목을 모두 덮어 턴당 약 1.5사실이다.
   - strict는 문진 커버리지가 −1~2%p(정보 −0.15~−0.3) 떨어질 수 있다 [추론].
   - 양성이면 둘째 항목은 기록하지 않는다(note2 규칙 이미 있음).

- **응급·입원 처치**(v3 GEN `disposition_luna` 응급/입원): followup이 "오늘 바로 응급실에서 외과 진료를 받으세요."로 바뀌고, caution과 생활 수칙은 뺀다.
- **소아**: 보호자 호칭("어머님")으로 말한다(v3 `title` 로직 유지).
- 걱정 문장 앞에 공감 어구를 넣어도 된다. 예) "걱정 많으셨을 텐데, 암보다 갑상샘 병 쪽이에요." 서술문이라 잘리지 않는다(F3). 질문 앞 공감은 금지.

### 5.3 설명 루프 알고리즘 (`v4.explain`)

```text
queue = [dx, options, link, concern, tests, caution, must*, lifestyle(묶이지 않았을 때)]   # 각 (key, text, pri)
tail  = [followup, warning, teach] + 미발화 must 중 '경고형'
answers = 0
while can_act:
    T = 미발화 tail;  left = turns_remaining
    if left <= len(T):                      say(T[0]); continue          # 강제 마무리
    if final 미발화 and left <= len(T) + 2: r = say(final)
                                            if 질문/두려움(r) and left-1 > len(T): answer(r)   # 예약 턴
                                            continue
    trim(queue, avail = left - len(T) - (2 if final 미발화 else 0))      # pri 낮은 것부터 제거
    k, text = queue.pop(0); r = say(text)
    if 질문/두려움(r) and answers < ANSWER_MAX(2):
        fk = faq_key(r); tgt = REORDER[fk]
        if tgt in queue: queue를 tgt부터 앞당김                           # 추가 턴 없음 (대부분)
        elif avail_after > 0: answer(r); answers += 1                    # FAQ → luna 1회 → 템플릿
```
- teach 응답에서 경고어가 하나도 맞지 않아도 다시 말하지 않는다. 마지막 턴이고, 효율 판정이 반복을 감점한다 [실측 sim].
- 질문 판정 = v2 `explain.is_question` + 두려움(두려|무서|걱정돼|불안해) + 끝이 `까요|나요|건가요|?`.

### 5.5 luna 프롬프트 (plan_say v4)
전문은 부록 D2. 요지는 다음과 같다.
1. 진단·감별, 시행한 진찰 목록과 소견, 양성·음성 사실, ICE 원문, KB 힌트, **정제한 hint_plan**(치료 섹션 제외, "검사·추적·경고·쉬운 설명 근거로만, 치료 줄에는 쓰지 말 것")을 넣는다.
2. lines는 키마다 후보 2개를 받는다: dx, options, link, concern, tests, caution, followup, warning, lifestyle.
3. FAQ 14키를 받는다(§5.4).
4. P를 받는다.
   - tests 3~7(name, reason)
   - follow_up: 재진·모니터링·즉시 내원
   - disposition: level + 이유. **시행한 진찰·문진만 근거, 하지 않은 진찰 소견을 '없다'고 쓰지 말 것**
   - treatment: KB 있으면 비움. 없으면 2줄 이내, 계열명, 조건부
   - education
5. 처방 확정·용량·성분명·단정 금지는 v3 문구 그대로.

### 5.6 검증기와 폴백
- **후보 선택**: 키마다 c1 → c2 순으로 `statement_ok(s)`(say_problem·safety_problem 0, safe_say 결과가 SAFE_SAY로 바뀌지 않음)를 처음 통과하는 문장을 쓴다.
- **키별 추가 검사**
  - dx: `say.dx_keywords(dx)` 중 하나 포함
  - warning: `WARN_RE` + 항목 ≥2(`warn_count`)
  - followup: `FOLLOWUP_RE` 또는 "오늘 바로 … 진료"(응급형)
  - concern: ICE에 질환명이 있으면 그 단어 포함
- **폴백 템플릿**(전부 ≤30자이며 검증기 통과. 테스트로 고정, 부록 C): v3 `fallback` 사전에 link·options·caution을 더한다.
- **KB 문장**(`kb.say`, `red_say`, `faq`)은 진단명이 KB와 맞을 때만 폴백으로 쓴다. 비공개 증례는 대부분 템플릿이나 luna 문장을 쓰게 된다.

### 5.7 v2c 안전 템플릿·필터와의 정합
- 설명 문장은 v2c `safe_say`(성분명 → 계열명, 구두 처방 → 안전 문구)와 v3 `safety_problem`을 둘 다 통과해야 한다. 그래서 v2c가 15점을 받은 금지 조건(용량·성분명·처방 확정·입원 불필요)을 그대로 지킨다.
- options 줄은 선택지 이름만 말하고 "시작해요"를 쓰지 않는다. caution 줄은 표준 안전 교육(무과립구증 → "열·목 통증이면 바로 연락")이라 안전 점수에 오히려 도움이 된다. C10 안전 감점 "부작용 교육을 다음 방문으로 미룸"을 해소한다 [추론].
- 기간("1~2년")은 숫자지만 용량 정규식(`mg|정|알|%|주분…`)에 걸리지 않는다. v3-gen C10에서 그대로 말했고 안전 12(sol 대리)에서 이 문장은 감점 사유가 아니었다 [실측].

### 7.4 90점이 어려운 이유와 최대치

- 정보 19.5(luna)는 sol 대리 I ≈ 15.4다. 예) H 0.55·X 0.70이면 문진 약 25문항 + 진찰 16 + 설명 10 = 약 52턴이 든다. 40턴 하드캡과 맞지 않는다.
- 소통으로 메우려면 13 이상이 필요하다. 지금까지 관측 최고는 luna 8.94, sol 대리 9다.
- 결론: **40턴에서 현실적 상한은 약 88~89(정보 18 + 소통 11.5 + 안전 15가 모두 잘 나온 경우), 중앙 약 85.7.** 90은 채점 변동(±2~3)이 유리하게 겹칠 때만 나온다(<10%).

## 10. 리스크·엣지케이스·버린 대안

**리스크**
1. 비공개 표에 템플릿이 없을 때 flex 행(최대 4턴)이 표 밖 진찰이 된다. 정상 소견만 돌아오고 점수가 없으며 효율 감점 가능성이 있다. 핵심 8행은 임상적으로 늘 정당하므로 손실을 flex로 한정했다. Z2(u12) 대 Z1로 크기를 본다.
2. 흉곽 시진·복부 시진 문구는 서버에서 써 본 적이 없다. 표 이름과 같아 매칭될 것으로 본다. 실패해도 거절보다는 표 밖 정상 소견일 가능성이 높다 [추측]. 샘플 검증 화면에 진찰 결과가 안 보이면 확인할 방법이 없다(로컬 시뮬은 이름 일치 매칭이라 통과).
3. 문진 14문항이면 진단 근거가 모자랄 수 있다. 특히 감별이 넓은 비공개 증례가 그렇다. 완화책은 sweep 후속, 지침 질문, 특이 진찰 5개다. 진단 하방 14.
4. luna 샘플 채점 변동이 영역당 ±1 수준이다 [추측]. 1회 비교로 결론을 내리지 말 것(§8.3 반복).
5. 로컬 Doctor(gpt-oss)는 JSON·한국어 품질이 luna보다 낮다. 폴백 경로가 많이 쓰이므로 로컬 점수는 낮게 나오는 것이 정상이다.
6. 지침 검색이 엉뚱한 문서를 잡을 수 있다(F6). "출처가 다르면 무시" 규칙과 정제로 줄이되 막지는 못한다.
7. 설명 문장에 치료 내용이 늘어 안전 감점이 생길 수 있다. 검증기 + 템플릿 + 테스트 S10으로 막는다.

**엣지케이스**
- 응급 처치(충수염 등): followup이 "오늘 바로 응급실/외과", 꼬리 경고는 유지, caution·생활은 뺀다.
- 소아: 보호자 호칭, 배경 블록 소아판, 의식·지남력 평가는 그대로 한다(C03 표에 있음 [실측]).
- 환자가 공감 턴에 질문으로 답함("큰 병인가요?"): 문진 중에는 답하지 않고 concern 줄에서 답한다.
- sweep이 처음부터 음성(C03): 남는 4턴은 본문 큐(배경·luna)로 간다.
- final 뒤 답이 다시 질문을 부름: 꼬리 3턴이 우선이라 답하지 못한다(F4 기준 드묾).
- 시간 부족: v3 가드(QUICK_EXPLAIN)로 빠른 경로.
- 진찰 거절이 연속: 블랙리스트 후 다음 후보. 진찰 단계는 E 턴을 남기고 멈춘다.

**버린 대안과 이유**
- **세션 조회(`client.session()`)의 effective_content 행 코드로 진찰을 적응 선택.** 진찰표 포함 여부를 실시간으로 알 수 있어 점수에는 강력하지만, 공지의 "비공개 평가 증례 … 정답을 추출하는 행위 금지"와 "수상 후보 코드 검토"에 걸릴 위험이 크다. 금지한다(현재 `v3.check_effective`처럼 제출 직전 SAY 절단 로그 확인 용도는 유지 가능).
- **두 질문을 한 SAY에.** 서버가 첫 질문만 남긴다 [실측].
- **공감을 질문 앞에 붙이기**(v2c 방식). 서버가 공감을 지운다(v2c 6/6 [실측]). 서술 턴이나 서술문 안에만 넣는다.
- **u12를 기본으로.** 공개 샘플 점수는 같지만, 특이 진찰을 놓치면 sol 효율 감점과 진단·안전 근거 약화가 생긴다. A/B 대안으로 둔다.
- **공감 턴 삭제(+1문항).** 공감 턴이 ICE 걱정 질문 역할도 겸해 사실상 문진 턴이다(3/3 [실측]).
- **code_js에 v3 이식.** §2.
- **44턴.** 사용자 지시 위반. 수치만 §7.2에 참고로 적음.
- **v3 GEN의 luna 완전 적응 진찰.** 진찰 커버리지가 34%로 떨어졌다 [실측].
